# Contributing

## Do not hand-edit the generated page

`index.html` is generated by `build.py`. Everything between the `BEGIN GENERATED`
and `END GENERATED` markers is overwritten, and CI fails if the committed page
disagrees with the sources.

To change content, change the source: either the upstream skill's own `SKILL.md`
frontmatter, or `sources.json`.

```bash
python3 build.py --write
```

## Adding a source repository

Add an entry to `sources.json` with its `repo`, `url`, `license`, the `subpath` to
walk, and a `flat_category` if all of its skills belong under one category. Then
regenerate, and record it in `THIRD_PARTY_NOTICES.md`. A source with no licence
recorded will fail the attribution test.

## Before you open a pull request

```bash
npm ci
npm run build:check
npm run lint:html
npm run lint:secrets
npm test
```

CI runs all of these. It uses no secrets, so it runs in full on forks.

## Rules the tests enforce

These are not stylistic preferences; each one is a test that will fail.

- `app.js` must not create content. It attaches motion to prerendered markup.
- The page must render completely with JavaScript disabled.
- With `prefers-reduced-motion`, pinning is off and the page is a plain list.
- No horizontal overflow at any of eight widths, in either motion mode.
- No axe violations at WCAG 2.1 AA, in either motion mode.
- No credential-shaped material anywhere in the tree or its history.
- Every card must name a licence, and every source must be credited.

## Never commit a credential

Deploy credentials come from GitHub Actions secrets, and AWS access is by OIDC
role assumption with no stored keys. `scripts/check-secrets.mjs` and gitleaks both
run on every push. If you need a new one, add it as a secret and document it in
`DEPLOYMENT.md` by name only.
